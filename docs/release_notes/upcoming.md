# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **Stop now works while Start is still running.** The two processes talked over a channel that handled one command at a time, so a Stop sent while a slow Start was still building its config was never read. "Stop cannot interrupt Start" was reported as a lifecycle problem and was not one: the command never arrived. Commands are now read as they come, so the one that must interrupt another no longer waits behind it.
- **A restarted background service no longer looks silent.** Messages are numbered per process, and the app remembered the last number it had seen. After a restart the new service counted from one while the app still held the old number, so every update compared as old and was discarded — the interface simply froze. Messages now say which service run they belong to, and the app follows the current one.
- **The app can no longer roll back to an older state.** The status snapshot and the live updates arrive over the same connection, and an update that arrived while the snapshot was in flight was overwritten by it. Updates that race the first snapshot are now held and replayed on top of it, so the newest state wins.
- **Restarting the service can no longer leave two of them running.** Shutdown released the old process before confirming it had exited, so a restart could start a second service over a live one — two processes sharing your config, your state files and the core. Shutdown now waits, escalates if needed, and reports failure instead of pretending.
- **A hand-edited config is no longer treated as disposable.** The launcher marked a config as "ours" and later rebuilt over it, so an edit you made by hand was silently deleted. The mark now records the exact content it was made for, and stops applying the moment the file changes.
- **Your subscription edits survive a refresh.** Refreshing all subscriptions rewrote the whole file, so a rename or a new URL entered while a slow provider was still being fetched was lost. Refreshes now only write the data they fetched, and leave your settings alone.
- **Installing a different core can no longer race a Start.** If a start had been accepted but had not yet launched, its version and config were checked against one file while the process ran another. Both now take the same lock, and installing a core is refused while anything lifecycle-related is in flight.
- **The app can no longer claim a subscription update succeeded when the config was never rebuilt.** A successful download followed by a failed rebuild reported success, so you were shown a new node count while the running core was still on the old configuration. The two outcomes are now reported separately.
- **Unpairing a daemon is now refused while it is in use, and really disconnects it.** Previously the button was merely disabled — and unpairing left the open connection alive, so the app said "not paired" while it could still control the daemon. The pairing is also now written before the credentials are deleted, so a failed save cannot leave a pairing that claims to exist and has no credentials.

- **A config the core would reject can no longer reach it from a nested rule.** The reference check now walks logical rules at any depth, validates inbound targets, and rejects a node whose tag collides with a name the core resolves itself (`direct`, `block`) — each one a way the original failure survived one level deeper.
- **A config that would have been refused by the core is now caught before it is used.** The background service applied a config whose `route.final` pointed at an outbound that did not exist; the core answered `default outbound not found: proxy-out` and stayed down. Every internal reference in a config is now resolved before it is written — node detours, group members, routing rules, the final target, DNS servers and rule-sets — and a dangling final target is repaired to a working one. This is the whole class of failure, not the one line that caused it.
- **A core failure is no longer reported as a crash, and no longer restarted in a loop.** A core that dies within its first second is a failed START, with the reason classified — an occupied port, missing permissions, a rejected config — instead of a crash to be retried. The state stays "starting" until the process has survived, so a bad config no longer produces a "Connected" flash followed by "Stopped".
- **Start and Stop tell the truth about what they are doing.** The command reply means the action was ACCEPTED, not finished: the core may still be rebuilding, authorizing, or waiting on the service. The spinner and disabled control are now held until the engine reports a settled state, so a slow start looks slow instead of looking broken.
- **Stopping the core confirms the process is actually gone.** Stop sent a terminate signal and reported success without ever checking whether the process had exited — so it could claim the VPN was down while the core was still running and still holding the tunnel. Termination now waits for a confirmed exit and escalates to a forced kill only when the graceful signal is ignored, verifying the process identity every time so a recycled PID is never signalled.
- **A core started in a previous session is watched, not assumed.** Reopening the app adopted the running core but had nothing watching it: the process was not the launcher's child, so if it died the screen kept saying "Connected" while Stop and Restart aimed at a process that no longer existed.
- **Failures now reach the app instead of a log file.** The launcher's UI and the app are separate processes, and nearly every core failure was reported only to the UI that is not running. One error source now carries the reason to the app, both live and across a restart, and each reason says what to do about it — an occupied port and a missing protected core copy need different actions.
- **Everything an error tells you is now actionable.** A refused config also says that your previous working config is still in use, and failures that cannot succeed on a retry — an occupied port, missing permissions — are no longer presented as retryable.
- **Switching engines is refused mid-operation instead of racing it.** Changing between the built-in core and the background service while a start, stop or restart is in progress had no correct outcome; it now waits for the operation to finish and says so.
- **The Proxies screen no longer breaks in daemon mode.** A daemon that does not implement the proxy-group RPC produced a red banner reading `unknown method GetGroups for service daemon.StartedService` on both the Proxies screen and Home. That is an engine limitation, not a fault, and it is now explained calmly with a pointer to Core Mode instead of reported as an error.
- **The launcher now asks the daemon what it can do, instead of assuming.** Probing the daemon on the reporting machine showed the mismatch was not one method but **eight**: `GetGroups`, `GetOutbounds`, `GetChains`, `GetPool`, `GetRules`, `URLTestOutbound`, `SetChainPositionEnabled` and `SetEndpointEnabled` all answered `Unimplemented`, while node switching worked. The launcher now discovers this per connection and disables only what is genuinely unavailable, so switching nodes keeps working while listing explains itself. No version numbers are compared — a custom build's version says nothing about its protocol, and the daemon here proved it.
- **Daemon status can now say "needs a newer daemon".** Previously the Daemon screen said **Active** while Proxies was disabled, with nothing connecting the two: the old check compared binaries and versions, which cannot see a daemon that is the right build but the wrong protocol. That is now its own row. Nothing is updated automatically — the launcher reports, you repair.
- **Home shows errors that matter.** A failed proxy read used to take over the main screen and push the core and config status aside. Feature-level failures now stay on the screen that owns them, each with its own Retry; Home keeps only blocking conditions.
- **Tighter, more even spacing throughout.** Row height, section gaps and page padding were reduced by roughly 10–15% and unified into one scale, so sections are spaced identically on every screen instead of 8pt here and 14pt there.
- **"Test All" is dramatically faster and shows live progress.** It used to measure nodes one after another, so a group with a few dead nodes could leave the panel unresponsive for a minute or more with only a spinner to look at. Nodes are now measured concurrently — bounded at 20 at a time, the setting the app already had and never used — and the button counts up ("Testing 12/36") while each row fills in the moment its own result arrives. A 40-node group at 100 ms per node goes from ~4 s to ~0.2 s in the measured benchmark, and the gap widens when nodes time out.
- **A node that fails says so, instead of "0 ms".** Timed-out nodes now read **Timed out** and errors read **Failed**, with the technical reason in the tooltip. Previously a failed measurement could display as 0 ms, which reads as the fastest node in the list. A node that measured 42 ms and then timed out is no longer shown as 42 ms — the old value is kept only as a last-known-good, never as the current result.
- **Measuring no longer loses its own answer.** The single-node test measured a latency, threw the number away and re-read the list hoping the core would echo it back — which it does not reliably do. The result is now stored and used directly, so a node you test immediately shows the value that was just measured, and it stays correct after a reload.
- **An engine that cannot measure says so, instead of breaking the screen.** Listing, switching and measuring were treated as one ability, so an engine missing any of them disabled the whole proxy screen. They are now separate: a daemon that can list but not test still shows its nodes and still lets you switch, with only the test action disabled and explained.
- **The proxy screen works in daemon mode again.** A daemon build that does not implement every proxy command left the node list and latency testing unavailable, even though the same background service was running your core and could answer both. Those actions now use the service's own local API — bound to `127.0.0.1` only, never your network — while switching keeps using the native channel. On the affected build, listing, single-node tests and "Test All" all work, with progress and results exactly as in classic mode.
- **Your config file is never rewritten for this.** The local API endpoint is only added to the copy handed to the background service; the file on disk stays byte-for-byte identical. If your config declares no Clash API, none is invented and the affected actions still report as unsupported rather than silently failing.
- **A remote background service is never reached through the local API.** If the daemon runs on another machine, `127.0.0.1` would mean this Mac, so the local fallback is refused outright and only the native channel is used.
- **The update prompt for the background service stops appearing when nothing is actually broken.** The daemon warns about missing internal commands; where those commands are covered by the local API, you keep every feature and are no longer told to update something that would change nothing.
- **The interface now speaks Chinese.** More → Application → **Language** switches between 跟随系统 / 简体中文 / English, applied immediately without a relaunch and remembered across launches. "Follow System" is a real choice, not an alias: the app keeps following macOS if you change the system language later.
- **The More page is organised by kind** rather than by accident: Automation (the toggles), Application (appearance and language, presented as one consistent pair), Files (the actions), About. Section headers now align to the content column instead of sitting off to one side, and every row shares one height, icon column and spacing scale.
- **Bring your own sing-box core.** Click the version on the Home screen and pick a sing-box binary: the launcher verifies it (runnable, right architecture, actually sing-box, and able to parse your current config), installs it atomically, and reports the version it actually installed. A rejected file leaves your working core untouched — byte for byte.
- **Import a subscription from a file.** Subscriptions → Add Subscription → **Import from File…** reads a local JSON, YAML or node-list file through the same parser a provider fetch uses. The imported source is a self-contained snapshot: it keeps working after you delete or move the original file, and it is never sent to the network, so it can never produce a provider error you did not cause.
- **Imported sources say what they are.** The row shows "Imported from <file>" instead of an empty URL, the edit screen omits the URL field and states that Refresh is not available for a file, and Update All skips them entirely. A missing core banner now offers **Load Core…** instead of only pointing at a folder.
- **A real visual redesign, not a re-skin.** The launcher now has its own application theme (light and dark palettes, macOS-like greys, #007AFF accent) instead of Fyne's defaults — which is why earlier layout work still looked like a stock toolkit. Every standard control inherits it.
- **Flat navigation.** The sidebar is one level of grouped items (Home / Network / Tools, About pinned at the bottom) with a soft rounded highlight on the selected item. The tree — and the admin-panel accent bar — are gone; detail navigation moved into the pages themselves.
- **A Home dashboard.** Instead of a proxy list beside a service panel, the app opens on a summary: connection state and the Start/Stop action, core and config details, and cards that lead to Proxies, Remote and Traffic. The proxy list gets the full page width where it belongs.
- **Content is no longer stretched edge to edge.** Pages keep a readable column (860 units, centred on wide windows) instead of cards spanning the whole display.
- **Settings and Diagnostics are grouped by meaning** into cards rather than a long form divided by rules; destructive actions are set apart.

- **Section headers now line up with the words under them.** The header of every section sat over the ICON column instead of the text column, so "Application" started noticeably to the left of "Appearance" and "Language" below it — and, worse, `MenuPickerRow` and `MenuActionRow` used a 10pt icon gap where the other rows used 8pt, so "the text column" was two different columns. Both are fixed by deriving the header inset from the same three tokens the rows use, so the title column is now defined exactly once. Section spacing was tightened by roughly 10% (row height unchanged, so click targets are unaffected).
- **A config written by an older JiejieBox is no longer reported as someone else's.** The launcher records who owns config.json in a marker file; a config written before markers existed has none, and "no marker" was being read as "another tool manages this" — an accusation about the user's own file. Ownership is now three-valued (**managed** / **unknown** / **external**): a missing or unreadable marker means *unknown*, and only an explicit statement that another tool owns the file counts as external. Unknown configs are never overwritten silently, and you can hand ownership to JiejieBox from Home after a prompt that states plainly that the launcher will then be able to rebuild and overwrite config.json.
- **If your config is provably this launcher's work, it is claimed automatically.** A legacy config is adopted when the current state rebuilds it exactly — a structural comparison, so formatting, key order and `//` comments may differ. This is a read-only check: it writes nothing, fetches nothing and changes no state, and a config that cannot be reproduced (for example one you edited by hand) stays *unknown* rather than being taken over. Note the honest limit: where the state does not carry the generated Clash API secret, a rebuild produces a *different* secret, so the config cannot be proven and stays *unknown* — use **Let JiejieBox Manage It**, which does not depend on that proof.
- **Start now tells you when it fails, instead of silently returning to "Start".** Pressing Start used to announce success immediately and then revert to the stopped state, with any failure written only to a log file — the exact "click does nothing" symptom. The backend now waits for the start to be genuinely committed (the process spawned, or the background service accepted the config), reports a **starting** state while it is in progress, and returns a real error when it fails. Home shows **Failed to start** with the reason — unacceptable configuration, unreachable service, rejected config, or **Clash API port 9090 already in use** — and the technical detail goes to the log and the tooltip. A rapid double click starts one core, not two.
- **The pre-start rebuild respects ownership.** Start and Restart used to rebuild config.json regardless of who owned it, even while Home said the file would not be touched. Both engines now honour the same ownership rule as the button.

### Technical / Internal
- SPEC 145. `ui/design.Theme` implements `fyne.Theme` with explicit light/dark palettes and the app's radii; `Font()`/`Icon()` delegate to the default theme (swapping fonts would break metrics on Windows/Linux). Installed from `main.go` — `core/uiservice` is L2 and must not import `ui/` (L7), so the stock `SetTheme` call there was removed rather than left to overwrite it.
- `RouteID` separates presentation routes from business domains: `selectSection` runs only when the domain actually changes, so Home → Proxies → Traffic neither re-applies scope/transport nor re-polls.
- New primitives: `MaxWidthLayout` (constrains and centres content, never its `MinSize`), `Card`/`ClickableCard`/`CardRow`, `SegmentedNav`, `StatusBadge`, primary/secondary/ghost/icon actions, `tintResource` (recolours `currentColor` SVGs so one icon serves normal and selected states).
- Navigation semantics preserved mechanically: the entire body of `app.tabs.OnSelected` moved verbatim into `App.selectSection` (`ui/navigation.go`). The sidebar and the retained (now off-screen) `AppTabs` both call that single method, so there is exactly one implementation of scope → panel activation → transport → refresh, in the original order.
- Pages are constructed once and swapped through a content host, so switching sections keeps scroll position, field contents and expanded sections.
- Collapsed sidebar parents keep the selected highlight while their child is active, and clicking a parent only expands it — it never changes the page.
- The core status indicator moved from the emoji tab title (▶️/⏸️) to a sidebar footer that projects `AppController.RunningState` — no second copy of the state.
- All sizes are Fyne logical units. No `canvas.Scale()`, no Retina multiplier, no `runtime.GOOS` branch for DPI, and `FYNE_SCALE` is never set.
- `docs/ARCHITECTURE.md` updated (L6/L7 rows, VpnStateChanged subscriber).
- macOS frontend localization: `Models/Localization.swift` holds one `enum L` with two exhaustive tables (en / zh-Hans), so a missing translation is a compile error rather than a blank label. `LanguageStore` is an `@Observable` class persisted in `UserDefaults` under `appLanguage`; `AppLanguage.system` resolves through `Locale.preferredLanguages` on every read, so "follow system" stays a live choice. Views read the resolved language from a SwiftUI environment value, which is what makes the switch take effect without a relaunch.
- Typography and spacing became tokens (`Views/Typography.swift`): a named text scale plus `Metrics` spacing values. Section headers are inset by `rowPaddingH` so the header column and the row icon column coincide by construction, not by two numbers that happen to match.
- Two latent defects were fixed while localizing, both of which worked only in English: the Core Mode rows compared the engine against the rendered label (`== "Daemon"`, `== "Classic"`) and the daemon status row against `status.summary == "Ready"`. Both now branch on protocol identifiers (`core.backend`, `DaemonStatus.nextStep`), and `AppModel.coreModeLabel(_:)` no longer capitalizes a wire value into English UI text.
- New guards in the Go suite (`backend/service/localization_test.go`), following the existing pattern for Swift invariants, since this toolchain cannot run `swift test`: no hardcoded user-facing literal in a view, the zh table really contains Chinese, both tables cover the same keys with no `default` branch, no key maps to an empty string, no font bypasses the token scale, and no view compares against a rendered label.
- Custom core import (`backend/service/core_import.go`) is a validate → stage → probe → atomic-rename transaction: nothing opens the destination for writing until the candidate is fully verified, so every failure path leaves the installed core byte-identical. The architecture check is Mach-O via `debug/macho` (fat slice or thin), never the `file` command; `CoreImportSupported()` reports false off macOS so the capability block stays honest. A successful swap invalidates the three binary-derived caches — `installedCoreVersionCache` does not self-expire on mtime, so without this the UI would keep reporting the old version for the rest of the session.
- Local subscription import (`backend/service/subscription_import.go`) reuses `DecodeSubscriptionContent` → `MaterializeSubscriptionBody`, i.e. exactly the pipeline a network refresh runs; only the byte source differs, and parsing happens before the state lock is taken so a large file cannot stall a concurrent refresh. The source is persisted as `kind: subscription` with `input_kind: local_snapshot` and an empty URL.
- `SubscriptionInputKind` / `state.CanRefreshSubscription` is the single source of truth for refreshability. Every fetch path (manual refresh, Update All, auto-update, warm-up) asks it instead of testing `url != ""`, which would have sent local snapshots to the network with an empty URL. Legacy records with no `input_kind` read as `remote`, so no migration is required. `state.SourceLabel` fixes two message sites that printed an empty URL as the source's name.
- New protocol methods `import_core_file` / `import_subscription_file` with capabilities `core_import` / `local_subscription_import`; `SubscriptionDTO` gained `input_kind`, `can_refresh`, `filename`. Swift budgets are explicit (45 s / 30 s) and well above the backend's additive worst case, because a timeout that fires mid-swap would report failure for a swap that succeeded. `docs/IMPORT_FLOW_AUDIT.md` records what is verified by test, by IPC and by reading only.

- **Stopping the VPN can no longer be reported as done while the core is coming back.** A restart takes the core down and brings it up again, and "down" looks exactly like a completed stop. A stop pressed during a restart was confirmed as successful moments before a new core appeared. The stop now asks *why* the core went down, and only a deliberate user stop ends it.
- **Switching engines no longer abandons a running core.** If the core crashed and was on its way back when you switched to the daemon engine, the switch left it holding the tunnel while the daemon's core started beside it — two cores, one VPN. Closing an engine now stops what it still owns.
- **The launcher no longer reports "stopped" for a VPN that is running.** The state was derived from a phase that does not describe whether a *process* exists, so an adopted root core could read as stopped: a clean Start button over an actively routed machine. The state now asks what the launcher actually launched and has not confirmed dead.
- **A core failure discovered a second too late can no longer disable one of your nodes.** A late "the core rejected the config" message arriving after you had already switched engines still removed a node from your working set. The launcher now checks it still owns the engine before changing anything.
- **An unreadable configuration no longer silently starts without privileges.** If the launcher could not tell whether your config needs TUN, it assumed it did not and started the core unprivileged — failing far from the cause. It now refuses and tells you why.
- **A start that was declined now says so.** Several preconditions (another core already running, a required authorization, a missing protected copy) explained themselves through a dialog. Without a dialog there was nothing: the button simply returned to Start. Those reasons now reach the interface with a stable identity and a localizable message.
- **The tunnel is stopped even if the interface gave up waiting.** The operation timeout bounded nothing: the waits that actually take time could not be interrupted. A stop now always runs to completion, and a timeout stops *waiting* rather than cancelling the work.
- **A crash is judged by its own log, not a previous core's.** Logs are appended across restarts, so an old fatal message could be read as the cause of a new, unrelated crash — and a transient failure could be treated as a permanent one that never restarts. Only the current run's output is considered now.
- **"Needs rebuilding" is decided by content, not by the clock.** A configuration changed immediately after it was built looked fresh, so the launcher never offered the rebuild. The check now compares what was built against what is on disk.
- **A stale proxy reload can no longer act on the wrong engine.** Two background reloads waited two seconds with nothing tying them to the engine that asked for them; a stop, switch or restart inside that window let them run against a runtime that never requested them.

## RU
### Основное
- **Stop теперь работает, пока Start ещё выполняется.** Два процесса общались по каналу, который обрабатывал одну команду за раз, поэтому Stop, отправленный во время медленного Start, просто не читался. Это выглядело как проблема жизненного цикла, но ею не было: команда не доходила. Команды теперь читаются сразу, и та, что должна прервать другую, больше не ждёт за ней.
- **Перезапущенная служба больше не выглядит «молчащей».** Сообщения нумеруются в пределах процесса, а приложение помнило последний увиденный номер. После перезапуска новая служба начинала с единицы, приложение держало старое число — и все обновления отбрасывались как устаревшие, интерфейс просто замирал. Теперь сообщения несут идентификатор запуска, и приложение следует за текущим.
- **Приложение больше не может откатиться к старому состоянию.** Снимок состояния и живые обновления приходят по одному соединению, и обновление, пришедшее во время отправки снимка, им же и перезатиралось. Такие обновления теперь придерживаются и применяются поверх снимка — побеждает самое свежее состояние.
- **Перезапуск службы больше не может оставить две работающие.** Завершение освобождало старый процесс, не убедившись, что он вышел, поэтому перезапуск мог поднять вторую службу поверх живой — два процесса на одних файлах состояния, конфиге и ядре. Теперь завершение ждёт, при необходимости ужесточается и сообщает о неудаче вместо видимости успеха.
- **Конфиг, отредактированный вручную, больше не считается расходным.** Лаунчер помечал конфиг как «свой» и затем перестраивал поверх него, поэтому ваша правка молча удалялась. Теперь метка хранит точное содержимое, для которого была поставлена, и перестаёт действовать, как только файл изменился.
- **Ваши правки подписок переживают обновление.** Обновление всех подписок перезаписывало файл целиком, поэтому переименование или новый URL, введённые во время загрузки медленного провайдера, терялись. Теперь обновление пишет только то, что загрузило, и не трогает ваши настройки.
- **Установка другого ядра больше не гоняется со Start.** Если запуск был принят, но процесс ещё не стартовал, версия и конфиг проверялись по одному файлу, а работал другой. Теперь и то и другое берут одну блокировку, а установка ядра отклоняется, пока что-либо, связанное с жизненным циклом, выполняется.
- **Приложение больше не может сообщить об успешном обновлении подписок, когда конфиг не перестроен.** Успешная загрузка с последующей неудачной пересборкой сообщала об успехе: вам показывали новое число узлов, тогда как ядро работало на старом конфиге. Теперь эти два исхода сообщаются раздельно.
- **Отвязка демона теперь отклоняется, пока он используется, и действительно разрывает соединение.** Раньше кнопка была просто неактивна — а отвязка оставляла открытое соединение живым, и приложение говорило «не связано», продолжая управлять демоном. К тому же связка теперь записывается до удаления учётных данных, поэтому неудачное сохранение не может оставить связку, которая заявляет о себе и не имеет учётных данных.

- **Конфиг, который ядро отвергло бы, больше не дойдёт до него из вложенного правила.** Проверка ссылок теперь обходит логические правила на любой глубине, проверяет цели inbound и отвергает узел, чей тег совпадает со встроенным именем ядра (`direct`, `block`) — каждый из этих случаев был способом исходной ошибки выжить на уровень глубже.
- **Конфиг, который ядро отвергло бы, теперь отсекается до использования.** Фоновая служба применила конфиг, у которого `route.final` указывал на несуществующий outbound; ядро ответило `default outbound not found: proxy-out` и не поднялось. Теперь перед записью разрешаются все внутренние ссылки конфига — detour узлов, состав групп, правила маршрутизации, финальная цель, DNS-серверы и rule-set; висячая финальная цель заменяется на рабочую. Это весь класс ошибки, а не одна строка, которая её вызвала.
- **Падение ядра больше не выдаётся за краш и не перезапускается в цикле.** Ядро, умершее в первую секунду, — это неудачный ЗАПУСК с распознанной причиной (занятый порт, нет прав, конфиг отвергнут), а не краш для повтора. Состояние остаётся «запускается», пока процесс не выживет, поэтому плохой конфиг больше не даёт вспышку «Подключено» и сразу «Остановлено».
- **Запуск и остановка честно показывают, что происходит.** Ответ на команду означает, что действие ПРИНЯТО, а не завершено: ядро может ещё пересобираться, ждать авторизации или ответа службы. Индикатор и заблокированная кнопка теперь держатся, пока движок не сообщит об устойчивом состоянии, поэтому медленный запуск выглядит медленным, а не сломанным.
- **Остановка ядра подтверждает, что процесс действительно завершился.** Остановка посылала сигнал и сообщала об успехе, ни разу не проверив, вышел ли процесс, — то есть могла объявить VPN выключенным, пока ядро работало и держало туннель. Теперь завершение ждёт подтверждённого выхода и переходит к принудительному уничтожению, только если мягкий сигнал проигнорирован; личность процесса проверяется каждый раз, поэтому переиспользованный PID никогда не будет убит.
- **Ядро, запущенное в прошлой сессии, теперь наблюдается, а не предполагается.** При открытии приложения работающее ядро принималось, но наблюдать за ним было некому: процесс не был дочерним, поэтому после его смерти экран продолжал показывать «Подключено», а Остановка и Перезапуск целились в несуществующий процесс.
- **Ошибки теперь доходят до приложения, а не только в лог.** Интерфейс лаунчера и приложение — разные процессы, и почти каждая ошибка ядра сообщалась только тому интерфейсу, которого нет. Теперь один источник ошибок доносит причину до приложения — и сразу, и после перезапуска, — и каждая причина говорит, что делать: занятый порт и отсутствующая защищённая копия ядра требуют разных действий.
- **Всё, что сообщает ошибка, теперь можно выполнить.** Отвергнутый конфиг дополнительно говорит, что прежний рабочий конфиг продолжает использоваться, а ошибки, которые не пройдут при повторе (занятый порт, нет прав), больше не подаются как повторяемые.
- **Смена движка отклоняется во время операции, а не гонится с ней.** Переключение между встроенным ядром и фоновой службой во время запуска, остановки или перезапуска не имело корректного исхода; теперь оно ждёт завершения операции и сообщает об этом.
- **Экран прокси больше не ломается в daemon-режиме.** Демон без RPC списка групп выдавал красный баннер `unknown method GetGroups for service daemon.StartedService` и на экране прокси, и на главной. Это ограничение ядра, а не сбой: теперь оно объясняется спокойно, со ссылкой на «Режим ядра», вместо ошибки.
- **Лаунчер спрашивает демон, что тот умеет, вместо предположений.** Проба демона на машине, где воспроизвёлся дефект, показала: расхождение не в одном методе, а в **восьми** — `GetGroups`, `GetOutbounds`, `GetChains`, `GetPool`, `GetRules`, `URLTestOutbound`, `SetChainPositionEnabled` и `SetEndpointEnabled` отвечали `Unimplemented`, тогда как переключение узлов работало. Теперь лаунчер выясняет это на каждое соединение и отключает только действительно недоступное: переключение узлов продолжает работать, а список объясняет себя. Версии не сравниваются — версия кастомной сборки ничего не говорит о её протоколе, и демон на этой машине это доказал.
- **Статус демона умеет сказать «нужен демон новее».** Раньше экран демона показывал **Active**, пока прокси были отключены, и связать одно с другим было нечем: прежняя проверка сверяла бинарники и версии и не видит демон, который той же сборки, но другого протокола. Теперь это отдельная строка. Автоматически ничего не обновляется — лаунчер сообщает, починка за пользователем.
- **Главная показывает только важные ошибки.** Неудачное чтение прокси перехватывало главный экран и вытесняло состояние ядра и конфига. Теперь ошибки уровня функции остаются на своём экране и имеют собственный «Повторить»; на главной — только блокирующие условия.
- **Плотнее и ровнее по всему интерфейсу.** Высота строк, отступы между секциями и поля страницы уменьшены примерно на 10–15% и сведены в одну шкалу, поэтому секции расположены одинаково на всех экранах, а не 8pt здесь и 14pt там.
- **«Проверить все» стало радикально быстрее и показывает прогресс.** Узлы мерились строго по очереди: группа с несколькими мёртвыми узлами оставляла панель неотзывчивой на минуту и дольше, а из обратной связи был только крутящийся индикатор. Теперь узлы измеряются параллельно — не более 20 одновременно, тем самым значением, которое в приложении уже было и никогда не использовалось, — а на кнопке идёт счёт («测速 12/36» / «Testing 12/36»), и каждая строка заполняется сразу, как только приходит её результат. Группа из 40 узлов при 100 мс на узел: ~4 с → ~0,2 с в измеренном бенчмарке, и разрыв растёт, когда узлы отваливаются по таймауту.
- **Узел, который не ответил, так и говорит — вместо «0 ms».** Таймаут теперь отображается как **超时 / Timed out**, ошибка — как **失败 / Failed**, техническая причина — в подсказке. Раньше неудачное измерение могло показаться как 0 мс, то есть как самый быстрый узел в списке. Узел, который мерился 42 мс, а потом ушёл в таймаут, больше не показывается как 42 мс: старое значение хранится только как «последнее успешное», но не как текущий результат.
- **Измерение больше не теряет собственный ответ.** Одиночная проверка измеряла задержку, выбрасывала число и перечитывала список в надежде, что ядро его вернёт, — а оно возвращает не всегда. Теперь результат сохраняется и используется напрямую: проверенный узел сразу показывает только что измеренное значение и сохраняет его после перезагрузки.
- **Ядро, которое не умеет мерить, говорит об этом, а не ломает экран.** Список, переключение и измерение считались одной способностью, поэтому отсутствие любой из них отключало весь экран прокси. Теперь это разные способности: демон, который умеет список, но не умеет тест, по-прежнему показывает узлы и позволяет переключаться — недоступно только измерение, и оно объяснено.
- **Экран прокси снова работает в режиме демона.** Если сборка демона не реализует часть proxy-команд, список узлов и проверка задержки были недоступны — хотя та же фоновая служба запускала ваше ядро и умела и то, и другое. Теперь эти действия используют собственный локальный API службы, привязанный только к `127.0.0.1` и никогда — к сети, а переключение по-прежнему идёт по штатному каналу. На затронутой сборке работают список, проверка одного узла и «全部测速 / Test All» — с тем же прогрессом и результатами, что и в classic-режиме.
- **Ваш файл конфигурации для этого не переписывается.** Локальный endpoint добавляется только в копию, которая передаётся фоновой службе; файл на диске остаётся побайтово тем же. Если в конфиге нет Clash API, он не выдумывается, и затронутые действия по-прежнему честно сообщают о недоступности вместо тихого отказа.
- **Удалённая фоновая служба никогда не доступна через локальный API.** Если демон работает на другой машине, `127.0.0.1` означал бы этот Mac, поэтому локальный fallback отклоняется полностью и используется только штатный канал.
- **Предложение обновить фоновую службу больше не появляется, когда ничего не сломано.** Демон сообщает об отсутствующих внутренних командах; там, где их покрывает локальный API, у вас остаются все возможности, и обновлять то, что ничего не изменит, больше не предлагается.
- **Интерфейс теперь говорит по-китайски.** More → Application → **Language** переключает 跟随系统 / 简体中文 / English: применяется сразу, без перезапуска, и запоминается. «跟随系统» — это настоящий выбор, а не синоним одного из языков: приложение продолжит следовать системе, если язык системы изменится позже.
- **Страница More организована по смыслу**, а не «как получилось»: Automation (переключатели), Application (внешний вид и язык — одной согласованной парой), Files (действия), About. Заголовки секций выровнены по текстовой колонке строк, а все строки используют одну высоту, колонку иконок и шкалу отступов.
- **Своё ядро sing-box.** Клик по версии на главном экране — и выбираешь бинарь sing-box: лаунчер проверяет его (запускается, верная архитектура, действительно sing-box, умеет прочитать текущий конфиг), ставит атомарно и показывает ту версию, которая реально установилась. Отклонённый файл не трогает рабочее ядро — побайтово.
- **Импорт подписки из файла.** Подписки → Add Subscription → **Import from File…** читает локальный JSON, YAML или список ссылок тем же парсером, что и загрузка от провайдера. Импортированный источник — самодостаточный снимок: он продолжает работать после удаления или переноса исходного файла и никогда не уходит в сеть, поэтому не может породить ошибку провайдера, которой не было.
- **Импортированные источники говорят, что они такое.** В строке — «Imported from <file>» вместо пустого URL, на экране правки нет поля URL и прямо сказано, что Refresh для файла недоступен, а Update All их пропускает. Баннер «ядро не найдено» теперь предлагает **Load Core…**, а не только папку.
- **Настоящий визуальный редизайн, а не перекраска.** У лаунчера появилась своя тема приложения (светлая и тёмная палитры, macOS-подобные серые, акцент #007AFF) вместо дефолтной Fyne — именно поэтому прошлые правки вёрстки всё равно выглядели как «стандартный тулкит». Тема наследуется всеми стандартными контролами.
- **Плоская навигация.** Сайдбар — один уровень пунктов, сгруппированных заголовками (Главная / Сеть / Инструменты, «О программе» прижат внизу), выбранный пункт подсвечен мягкой скруглённой заливкой. Дерево и полоса-индикатор в стиле админки убраны; детализация переехала на сами страницы.
- **Дашборд на главной.** Вместо списка узлов рядом со служебной панелью приложение открывается сводкой: состояние и кнопка Start/Stop, сведения о ядре и конфиге, карточки-переходы к Прокси, Remote и Трафику. Список узлов получает всю ширину страницы, где он и нужен.
- **Контент больше не растянут от края до края.** Страницы держат читаемую колонку (860 units, по центру на широком окне) вместо карточек на весь экран.
- **Настройки и Диагностика сгруппированы по смыслу** в карточки, а не в длинную форму с линиями; опасные действия вынесены отдельно.

### Техническое / Внутреннее
- SPEC 144. Новый пакет `ui/design`: `metrics.go` (4-й ритм отступов, радиусы, геометрия сайдбара, доли сплита, размеры окна), `typography.go` (пять уровней текста), `colors.go` (semantic-цвета из активной темы), `sidebar.go`, `page.go` (PageHeader, SectionCard, StatusBadge).
- Семантика навигации сохранена механически: тело `app.tabs.OnSelected` целиком переехало в `App.selectSection` (`ui/navigation.go`). Сайдбар и оставленный (уже невидимый) `AppTabs` зовут один и тот же метод, поэтому реализация «область → активация панели → транспорт → refresh» ровно одна и в исходном порядке.
- Страницы создаются один раз и подменяются через content host: переключение разделов сохраняет позицию скролла, введённый текст и раскрытые секции.
- Свёрнутый родитель в сайдбаре сохраняет подсветку, пока активен его подпункт; клик по родителю только разворачивает его и никогда не меняет страницу.
- Индикатор состояния ядра переехал из emoji-заголовка вкладки (▶️/⏸️) в нижнюю строку сайдбара и проецирует `AppController.RunningState` — второй копии состояния нет.
- Все размеры — в Fyne logical units. Без `canvas.Scale()`, без множителя Retina, без ветвлений по `runtime.GOOS` для DPI; `FYNE_SCALE` не выставляется.
- Обновлён `docs/ARCHITECTURE.md` (строки L6/L7, подписчик VpnStateChanged).
- Локализация macOS-фронтенда: `Models/Localization.swift` — один `enum L` с двумя исчерпывающими таблицами (en / zh-Hans), поэтому отсутствующий перевод это ошибка компиляции, а не пустая подпись. `LanguageStore` — `@Observable`-класс с хранением в `UserDefaults` под ключом `appLanguage`; `AppLanguage.system` резолвится через `Locale.preferredLanguages` при каждом чтении, поэтому «跟随系统» остаётся живым выбором, а не превращается в жёстко зафиксированный язык. Вью берут язык из SwiftUI-окружения — именно поэтому переключение действует без перезапуска.
- Типографика и отступы стали токенами (`Views/Typography.swift`): именованная шкала текста плюс значения отступов в `Metrics`. Заголовок секции получает отступ `rowPaddingH`, поэтому колонка заголовка и колонка иконок строк совпадают по построению, а не потому, что два числа случайно равны.
- При локализации исправлены два скрытых дефекта, каждый из которых работал только на английском: строки Core Mode сравнивали движок с отрисованной подписью (`== "Daemon"`, `== "Classic"`), а строка статуса демона — с `status.summary == "Ready"`. Теперь ветвление идёт по идентификаторам протокола (`core.backend`, `DaemonStatus.nextStep`), а `AppModel.coreModeLabel(_:)` больше не капитализирует значение протокола в английский текст интерфейса.
- Новые guard-тесты в Go-наборе (`backend/service/localization_test.go`) по уже принятому шаблону для Swift-инвариантов (на этом тулчейне `swift test` не собирается): отсутствие захардкоженных пользовательских строк во вью, наличие китайского в zh-таблице, совпадение набора ключей в обеих таблицах без ветки `default`, отсутствие пустых значений, использование только токенов шрифта и запрет сравнений с отрисованными подписями.
- Импорт ядра (`backend/service/core_import.go`) — транзакция «проверить → подготовить → прощупать → атомарный rename»: до полной проверки кандидата пункт назначения не открывается на запись, поэтому любая ошибка оставляет установленное ядро побайтово тем же. Проверка архитектуры — через `debug/macho` (fat-срез или thin), без команды `file`; `CoreImportSupported()` возвращает false вне macOS, чтобы блок capability не обещал лишнего. Успешная замена сбрасывает все три кэша, производных от бинаря: `installedCoreVersionCache` не истекает по mtime, и без сброса UI показывал бы старую версию до конца сессии.
- Импорт подписки из файла (`backend/service/subscription_import.go`) переиспользует `DecodeSubscriptionContent` → `MaterializeSubscriptionBody`, то есть ровно тот же конвейер, что и сетевой fetch; отличается только источник байт, а разбор идёт до взятия блокировки состояния, чтобы большой файл не тормозил параллельный refresh. Источник сохраняется как `kind: subscription` с `input_kind: local_snapshot` и пустым URL.
- `SubscriptionInputKind` / `state.CanRefreshSubscription` — единственный источник правды о refresheability. Все пути fetch (ручной Refresh, Update All, автообновление, прогрев) спрашивают его, а не проверяют `url != ""`: иначе локальный снимок ушёл бы в сеть с пустым URL. Legacy-записи без `input_kind` читаются как `remote`, миграция не нужна. `state.SourceLabel` чинит два места, где в сообщение подставлялся пустой URL вместо имени источника.
- Новые методы протокола `import_core_file` / `import_subscription_file` и capability `core_import` / `local_subscription_import`; в `SubscriptionDTO` добавлены `input_kind`, `can_refresh`, `filename`. Таймауты на стороне Swift заданы явно (45 с / 30 с) и с запасом над суммарным худшим случаем бэкенда: сработавший посреди замены таймаут сообщил бы об ошибке там, где замена прошла. `docs/IMPORT_FLOW_AUDIT.md` фиксирует, что подтверждено тестом, что — IPC, а что — только чтением кода.

- **Заголовки секций выровнены по тексту под ними.** Заголовок каждой секции стоял над колонкой ИКОНКИ, а не над текстовой, поэтому «应用» начинался заметно левее «外观» и «语言» под ним; вдобавок `MenuPickerRow` и `MenuActionRow` использовали отступ между иконкой и текстом 10pt там, где остальные строки — 8pt, то есть «текстовая колонка» была двумя разными колонками. Теперь отступ заголовка выводится из тех же трёх токенов, что и строки, поэтому колонка заголовков определена ровно в одном месте. Межсекционные отступы подтянуты примерно на 10% (высота строки не изменилась — область нажатия та же).
- **Конфиг, созданный более старой версией JiejieBox, больше не объявляется чужим.** Владелец config.json записывается в файл-маркер; у конфига, собранного до появления маркеров, его нет, а «маркера нет» читалось как «файлом управляет другой инструмент» — обвинение в адрес собственного файла пользователя. Теперь владение трёхзначное (**managed** / **unknown** / **external**): отсутствующий или нечитаемый маркер означает *unknown*, и только явное указание, что файл принадлежит другому инструменту, считается external. Неизвестные конфиги никогда не перезаписываются молча, а с главного экрана можно передать владение JiejieBox — после подтверждения, прямо сообщающего, что лаунчер сможет пересобирать и перезаписывать config.json.
- **Если конфиг доказуемо собран этим лаунчером, он присваивается автоматически.** Устаревший конфиг принимается, когда текущее состояние воспроизводит его в точности — сравнение структурное, поэтому форматирование, порядок ключей и комментарии `//` могут отличаться. Проверка только читает: ничего не пишет, ничего не скачивает и не меняет состояние; конфиг, который не воспроизводится (например, отредактированный вручную), остаётся *unknown*, а не присваивается. Честное ограничение: если в состоянии нет сгенерированного секрета Clash API, пересборка даёт ДРУГОЙ секрет, поэтому конфиг доказать нельзя и он остаётся *unknown* — используйте пункт **设为 JiejieBox 管理**, который от этого доказательства не зависит.
- **Запуск теперь сообщает о неудаче, а не молча возвращается к «Запустить».** Нажатие «Запустить» мгновенно сообщало об успехе и затем откатывалось к состоянию «остановлено», а любая ошибка уходила только в лог — ровно симптом «кнопка ничего не делает». Теперь бэкенд ждёт реального подтверждения запуска (процесс порождён либо служба приняла конфиг), показывает состояние **запускается**, пока это происходит, и возвращает настоящую ошибку при неудаче. На главном экране появляется **启动失败** с причиной — недопустимая конфигурация, недоступная служба, отклонённый конфиг или **порт Clash API 9090 уже занят**; технические детали идут в лог и в подсказку. Быстрый двойной клик запускает одно ядро, а не два.
- **Предстартовая пересборка уважает владение.** Start и Restart пересобирали config.json независимо от владельца, даже когда главный экран утверждал, что файл не будет тронут. Оба движка теперь подчиняются тому же правилу владения, что и кнопка.
- **Остановка VPN больше не может быть объявлена выполненной, пока ядро возвращается.** Перезапуск опускает ядро и поднимает его снова, а «опущено» выглядит в точности как завершённая остановка. Остановка, нажатая во время перезапуска, подтверждалась как успешная за мгновение до появления нового ядра. Теперь остановка спрашивает, ПОЧЕМУ ядро ушло, и завершается только намеренной остановкой пользователя.
- **Смена движка больше не бросает работающее ядро.** Если ядро падало и возвращалось в момент переключения на демон, переключение оставляло его держать туннель, пока рядом поднималось ядро демона — два ядра, один VPN. Теперь закрытие движка останавливает то, чем он ещё владеет.
- **Лаунчер больше не показывает «остановлено» для работающего VPN.** Состояние выводилось из фазы, которая ничего не говорит о существовании ПРОЦЕССА, поэтому принятое root-ядро могло читаться как остановленное: чистая кнопка Start над активно маршрутизируемой машиной. Теперь состояние спрашивает, что именно было запущено и ещё не подтверждено мёртвым.
- **Отказ ядра, замеченный на секунду позже, больше не может отключить ваш узел.** Позднее сообщение «ядро отвергло конфиг», пришедшее после переключения движка, всё равно убирало узел из рабочего набора. Теперь перед любым изменением лаунчер проверяет, что всё ещё владеет движком.
- **Нечитаемая конфигурация больше не запускается молча без прав.** Если лаунчер не мог определить, нужен ли конфигу TUN, он считал, что не нужен, и запускал ядро без прав — падая далеко от причины. Теперь он отказывается и объясняет почему.
- **Отклонённый запуск теперь сообщает об этом.** Несколько предусловий (уже работающее ядро, требуемая авторизация, отсутствующая защищённая копия) объясняли себя диалогом. Без диалога не было ничего: кнопка просто возвращалась к Start. Теперь эти причины доходят до интерфейса со стабильным кодом и переводимым сообщением.
- **Туннель останавливается, даже если интерфейс перестал ждать.** Таймаут операции не ограничивал ничего: ожидания, которые действительно занимают время, нельзя было прервать. Теперь остановка всегда доводится до конца, а таймаут прекращает ОЖИДАНИЕ, а не саму работу.
- **Падение оценивается по своему логу, а не по логу предыдущего ядра.** Лог дописывается между перезапусками, поэтому старое фатальное сообщение могло быть прочитано как причина нового, не связанного с ним падения — и временный сбой принимался за постоянный, который никогда не перезапускается. Теперь учитывается только вывод текущего запуска.
- **«Нужна пересборка» решается по содержимому, а не по часам.** Конфигурация, изменённая сразу после сборки, выглядела свежей, поэтому лаунчер никогда не предлагал пересборку. Теперь собранное сравнивается с тем, что лежит на диске.
- **Устаревшая перезагрузка прокси больше не может сработать не на том движке.** Две фоновые перезагрузки ждали две секунды, ничем не будучи привязаны к движку, который их запросил; остановка, переключение или перезапуск в этом окне позволяли им отработать по рантайму, который их не запрашивал.
